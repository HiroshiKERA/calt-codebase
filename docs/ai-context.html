calt-codebase — AI Context Document

This document is for AI assistants answering questions about this repository (calt-codebase, an experiment repo built on the calt-x library). It contains the real directory tree, the house API (shared/), the per-task core/ contract, the exact way calt-x is used here, the config schemas, and known gotchas. Read this file to answer "how does this code work" questions.

For a beginner-friendly walkthrough see DOCUMENTATION.md. docs/ai-context.html is built from this file by python build_docs.py --site; rerun it after editing.

Organizing principle: each top-level directory is one task (one math problem). A task has core/ (reusable logic) and experiments/<name>/ (configs + scripts). Cross-task utilities live in shared/.

Note for older docs: this repo does not have an examples/ or src/ directory, a CustomTrainer file, an environment.yml, or Kaggle remote execution. Those belonged to a previous layout. By default, tokenization is the polynomial's printed string + per-digit numbers; the "C/E" (Coefficient/Exponent) expanded form is opt-in for groebner_basis and border_basis by pointing data.lexer_config at lexer_expanded.yaml.

2. The per-task core/ contract

Every task exposes the same five modules. Signatures below are the real ones.

2.1 core/generator.py — class …Generator with __call__(seed)

A callable class, not a function. Constructed with task params, then passed to DatasetPipeline(instance_generator=...), which calls it once per seed.

class GroebnerGenerator:
    def __init__(self, sampler: PolynomialSampler, num_polynomials: int = 2): ...
    def __call__(self, seed: int) -> tuple[list, list]:
        randstate.set_random_seed(seed)
        ...
        return F, G          # (problem, answer); lists are joined with ' | ' by CALT

class ParityGenerator:
    def __init__(self, n: int = 5): ...
    def __call__(self, seed: int) -> tuple[str, str]:
        random.seed(seed)
        ...
        return "2 0 1", "+1"   # plain strings

class BorderBasisGenerator:
    def __init__(self, sampler, num_polynomials=3,
                 use_fast_elimination=True, lstabilization_only=False): ...
    def __call__(self, seed: int) -> tuple[list, list]: ...

Contract: one arg seed: int; deterministic; returns (problem, answer). Each side may be str, a list (CALT joins via str() + ' | '), or a SageMath object (str() called automatically). Generators retry up to 100 seeds to skip degenerate samples (large-rational rejection for QQ Gröbner; non-0-dim ideals for border basis).

2.2 core/formatter.py

format_input(problem) -> str and format_target(answer) -> str. Used for tests/REPL/parsers — not by DatasetPipeline (which str()s objects itself). SEP is " | ".

2.5 core/train.py — run_training(...)

The function the scripts/train.py entry point calls. Drives the 4 CALT pipelines.

# parity:
def run_training(cfg: DictConfig, dryrun: bool = False) -> float

# border:
def run_training(cfg: DictConfig, data_cfg: DictConfig | None = None, dryrun: bool = False) -> float

# groebner (supports the lex variant):
def run_training(cfg, data_cfg=None, training_order="degrevlex", dryrun=False) -> float

Body of parity, the template and run_standard_training:

if dryrun: apply_dryrun_settings(cfg)
save_dir = cfg.train.get("save_dir", cfg.train.get("output_dir", "./results"))
os.makedirs(save_dir, exist_ok=True)
OmegaConf.save(cfg, os.path.join(save_dir, "train.yaml"))

io_pipeline = IOPipeline.from_config(cfg.data)
# (groebner lex only) io_pipeline.dataset_load_preprocessor = ChainLoadPreprocessor(...)
io_dict = io_pipeline.build()
model = ModelPipeline.from_io_dict(cfg.model, io_dict).build()
trainer_pipeline = TrainerPipeline.from_io_dict(cfg.train, model, io_dict).build()
trainer_pipeline.train()
trainer_pipeline.save_model()
return trainer_pipeline.evaluate_and_save_generation()   # float success rate

groebner_basis and border_basis have a second shape: they build the load preprocessor with build_load_preprocessor(...) (chaining TextToSage parsing, the C/E expanded form when lexer_expanded.yaml is used, and user hooks), and the IO pipeline with build_io_pipeline_with_cache(...), which picks a pre-tokenized cache, a strings cache or the raw text (the cache hash includes user_postprocessor_hash_contribution). Gröbner's run_training additionally suffixes save_dir and wandb.name with _{training_order}; for lex it builds the source ring from data_cfg.sampler and wires ChainLoadPreprocessor(TextToSageLoadPreprocessor, GroebnerLexOrderPreprocessor), and it raises if lex is combined with the expanded form.

4. How calt-x is used here (touchpoints)

This repo treats calt-x as a black box behind four pipelines. The exact imports and call sites used:

# dataset
from calt.dataset import DatasetPipeline
from calt.dataset.sagemath.utils.polynomial_sampler import PolynomialSampler

sampler = PolynomialSampler(**sampler_cfg)        # see §6 for sampler_cfg keys
sampler.get_ring()                                 # → SageMath PolynomialRing
sampler.sample(num_samples=k)                      # → list of polynomials
DatasetPipeline.from_config(cfg.dataset, instance_generator=generator).run()

# io
from calt.io import IOPipeline, ChainLoadPreprocessor, TextToSageLoadPreprocessor
io = IOPipeline.from_config(cfg.data)
io.dataset_load_preprocessor = <obj with process_sample>   # optional
io_dict = io.build()        # keys: tokenizer, train_dataset, test_dataset, data_collator

# models
from calt.models import ModelPipeline
model = ModelPipeline.from_io_dict(cfg.model, io_dict).build()   # model_type picks the model (generic: calt enc-dec)

# trainer
from calt.trainer import TrainerPipeline, apply_dryrun_settings
tp = TrainerPipeline.from_io_dict(cfg.train, model, io_dict).build()
tp.train(); tp.save_model()
rate = tp.evaluate_and_save_generation()           # float exact-match rate
tp.trainer                                          # underlying HF Trainer (add_callback, …)

# eval result loading
from calt.io.visualization.comparison_vis import load_eval_results

apply_dryrun_settings(cfg) mutates the config in place: 1 epoch, batch sizes ≤ 8, num_workers: 0, eval/save every 10 steps, 1000/100 train/test samples, a dryrun- prefix on the wandb name/group, and (since calt-x 1.6.1) always no_wandb: true, so a dryrun never logs to W&B.

evaluate_and_save_generation(max_length=None) generates up to 512 tokens, capped at what the model's positional embedding allows (a larger explicit max_length is capped with a warning). Pass max_length for answers longer than 512 tokens.

Exact internal signatures of these classes live in the installed calt package — verify against pip show calt-x / the library source rather than assuming, as the version is only pinned >=1.6.1.

4.1 Model types and custom embeddings

model.model_type selects the model (aliases in parentheses):

model_type Model
generic (transformer, calt) calt's standard encoder-decoder
bart HuggingFace BART
decoder_only (decoder) one causal stack over [problem, answer]; uses num_layers/num_heads/ffn_dim, falling back to the decoder/encoder keys
encoder_classifier (encoder_only) encoder + classification head (parity's train_encoder.yaml)
monomial (monomial_transformer) encoder-decoder over C/E monomials
monomial_decoder_only (monomial_decoder) decoder-only over C/E monomials

For the generic, decoder_only and encoder_classifier models, model.input_embedding_type (default token) and model.use_positional_embedding (generic/learned (default), sinusoidal, rope, none) select the embeddings. Register custom ones with calt.models.register_input_embedding / register_positional_embedding before building the model (parity's train_custom_embedding.py registers an input embedding this way).

5. lexer.yaml schema (real)

vocab:
  range:
    numbers: ["", min, max]    # [prefix, min, max] → number tokens; prefix usually ""
    # extra named ranges allowed, e.g. signed: ["", -1, -1]
  misc: ["+", "-", "*", "^", "x", "y", "|", "/"]   # literal operator/variable tokens
  special_tokens: {}
  flags:
    include_base_vocab: true
    include_base_special_tokens: true    # adds [PAD], <s>, </s>, [CLS] ([SEP] comes from the base vocab)

number_policy:
  attach_sign: true     # "-3" one token vs "- 3" two tokens
  digit_group: 1        # 0 = whole numbers; d >= 1 = groups of d digits (1 = each digit)
  allow_float: false    # defaults to true when omitted

strict: true            # raise on unknown character; false emits <unk> instead
include_base_vocab: true

Polynomial tasks (groebner, border): digit_group: 1, misc includes x y ^ * + - | (and / for QQ). Digit-level tokenization → any integer size. Parity: digit_group: 0, numbers: ["", 0, 20], misc ["+1"], signed: ["", -1, -1], strict: false.

lr_scheduler_type is passed to transformers as is (since calt-x 1.6.1; before that, every value except constant silently became linear, so parity's cosine only takes effect from 1.6.1). 7. Data format and on-disk outputs

Dataset text (train_raw.txt / test_raw.txt): one example per line,

<input> # <output>
  • # separates input from output (with surrounding spaces: " # ").
  • | separates list elements within a side (|).
  • Examples:
  • parity: 0 2 3 1 4 # +1
  • groebner: f1 | f2 # g1 | g2 | … | gk

Generation stats: train_stats.yaml / test_stats.yaml (YAML, not JSON): total_time, num_samples, samples_per_second, generation_time:{mean,std,min,max}.

Training outputs (<save_dir>/): the model weights (pytorch_model.bin, or model.safetensors with train.save_safetensors: true) with config.json, tokenizer.json and the tokenizer configs, checkpoint-*/, train.yaml (snapshot of the config used), and eval_results/step_*.json ([{"generated": ..., "reference": ...}, …]); the final evaluate_and_save_generation() also writes to eval_results/step_<global_step>.json (eval_results.json is only used when no step is known).

8. The three tasks (specifics)

parity groebner_basis border_basis
Input one-line perm 2 0 1 f1 \| f2 over k[x,y] g1 \| g2 \| g3 over GF(p)
Output +1 / -1 Gröbner basis g1 \| … border basis
Backend sympy sagemath sagemath
Storage plain text plain text plain text
Preprocessor none none by default (lex variant, expanded form, hooks: Chain) none by default (expanded form, hooks: Chain)
Generator class ParityGenerator(n) GroebnerGenerator(sampler, num_polynomials) BorderBasisGenerator(sampler, num_polynomials, …)
Experiments toy, scaling (n∈{5,7,10}), ablation toy, scaling, ablation (degrevlex/lex) toy, finite_field (GF 5/7/11/17/31), ablation
Algorithm inversions count SageMath ideal.groebner_basis() core/algorithm.py::BorderBasisCalculator (port of arXiv:2505.23696 Alg 4.1)
  • parity: sign(σ) = (−1)^(#inversions); count_inversions, permutation_parity helpers in core/generator.py.
  • groebner: QQ samples with ≥3-digit numerator/denominator rejected (_has_large_rational_coefficients, threshold 100). --training_order lex recomputes the basis in a lex ring at load time.
  • border: requires a 0-dimensional ideal (ideal.dimension() == 0), retried up to 100 seeds; BorderBasisCalculator does L-stable span → optimal order ideal via scipy.optimize.milp → basis transformation; uses sortedcontainers.SortedList.

The scripts/train.py of each experiment is a thin click wrapper: parity/scaling exposes --n (rewrites data paths + save_dir + wandb name); groebner/toy exposes --training_order {degrevlex,lex}, --data_config_path, --config_path, --dryrun.

9. templates/task_template/

Same layout as a real task, with TODOs. The runnable, consistent pattern:

  • core/generator.py::TaskGenerator(**params) with __call__(seed) (raises until filled).
  • core/parser.py::TaskParser.process_sample(source) — only if storing pickle/JSON.
  • core/train.py::run_training(cfg, dryrun=False) — sets dataset_load_preprocessor = TaskParser() (comment says remove for plain text).
  • experiments/toy/scripts/generate.py — builds TaskGenerator(**cfg.problem_generator) and runs DatasetPipeline.from_config(cfg.dataset, instance_generator=…).
  • experiments/toy/configs/data.yaml — has a problem_generator: {} block + dataset:.
  • README has the fill-in checklist.

To create a task: cp -r templates/task_template my_new_task, fill the core/ modules, edit the three configs, then generate.py → train.py --dryrun → evaluate.py.

10. Known issues, gotchas, and conventions

  • Run scripts from their scripts/ dir. Config paths are relative to it, and sys.path.insert(0, parents[4]) makes the repo root importable. Running from elsewhere breaks both.
  • Unknown character / OOV token: a symbol in the data isn't in lexer.yaml. Widen numbers or add to misc; set validate_train_tokens: true to fail fast.
  • max_sequence_length: polynomial bases get long (groebner toy uses 2048, border toy 512, parity 64). Nothing is truncated: with the default learned (or sinusoidal) positional embedding, sequences longer than 2 × max_sequence_length raise a ValueError (rope extrapolates, none has no limit).
  • GPU not used: see the GPU row in §0 (CUDA 13 torch on an old driver).
  • Determinism: set_seed enables deterministic algorithms + sets CUBLAS_WORKSPACE_CONFIG. Same root_seed ⇒ identical datasets.
  • SageMath RNG is global: generators call randstate.set_random_seed(seed) before sampling.
  • wandb: no_wandb: true removes wandb from report_to (other loggers such as tensorboard are kept; this also works on transformers v5, which ignores WANDB_DISABLED), or set WANDB_MODE=disabled. --dryrun never logs to W&B.
  • No src/, no examples/, no CustomTrainer.py, no environment.yml, no Kaggle remote in this repo (unlike the previous CALT layout). Custom training hooks go through shared/logging.py or by subclassing calt.trainer.trainer.Trainer.
  • Internal cross-references in code/docstrings to issac2026_experiments/* point at the upstream HiroshiKERA/calt@experiment/issac2026 branch the tasks were ported from — not files in this repo.

     (poly tasks) PolynomialSampler(**sampler) ; <Task>Generator(sampler, **problem_generator)
     DatasetPipeline.from_config(cfg.dataset, instance_generator=gen).run()
       for seed in 0..N-1 (parallel, n_jobs): problem,answer = gen(seed)
       serialize → "<input> # <output>" → train_raw.txt / test_raw.txt (+ *_stats.yaml)

2. TRAIN
   scripts/train.py → core/train.py::run_training(cfg, …)
     IOPipeline.from_config(cfg.data)[.dataset_load_preprocessor = …].build() → io_dict
     ModelPipeline.from_io_dict(cfg.model, io_dict).build()                   → model (by model_type)
     TrainerPipeline.from_io_dict(cfg.train, model, io_dict).build()
     .train() → .save_model() → .evaluate_and_save_generation() → float rate
     writes <save_dir>/{model weights, tokenizer.json, train.yaml, eval_results/step_*.json}

     # _<model_size> (ablation), _n<n> (parity scaling), _GF<p> (border finite_field)
     print exact-match rate ; show_examples(... successes=True/False)
